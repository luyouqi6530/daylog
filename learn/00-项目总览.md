# Daylog 项目总览

> 本文件是整个学习文档体系的入口，搞清楚"这个项目是什么、由什么组成、每个目录放什么"。

## 一、项目定位

**Daylog = 每日记录 + 心情追踪平台**。用户每天写一篇日记（Markdown，可配图），给心情打 1-5 分，打标签；系统提供心情曲线、记录热力图、标签云等统计可视化，并每周一自动用 AI 生成上周总结。

一句话概括技术亮点：**前后端分离 + JWT 认证 + Redis 缓存 + AI 集成 + Docker 部署的完整闭环项目**。

## 二、整体架构

```
┌─────────────────────────────────────────────┐
│  浏览器                                      │
│  Vue3 SPA（Vite 构建，Element Plus + ECharts）│
└──────────────────┬──────────────────────────┘
                   │  HTTP，请求统一带 /api 前缀
                   ▼
┌─────────────────────────────────────────────┐
│  Nginx 网关（生产）                          │
│  · 托管前端静态资源 + history 路由回退        │
│  · /api → 后端（去前缀）  · /files → 后端图片 │
└──────────────────┬──────────────────────────┘
                   │  （开发环境无此层：Vite 代理等价转发）
                   ▼
┌─────────────────────────────────────────────┐
│  Spring Boot 3 后端 (:8080)                  │
│  Controller → Service → Mapper 三层          │
│  Spring Security 过滤器链 + JWT 校验          │
└───┬──────────┬──────────┬──────────┬────────┘
    ▼          ▼          ▼          ▼
 MySQL 8     Redis      本地磁盘     DeepSeek
 (业务数据)  (缓存+黑名单) (图片上传)  (AI周报)
```

**为什么请求要带 /api 前缀再由代理去掉？**
统一标识"这是发给我后端的请求"，代理规则简单（只匹配 /api），前端代码里 baseURL 只有一个值（/api），开发环境（Vite 代理）与生产环境（Nginx 反代）行为完全一致，前端代码零改动切换环境。

## 三、技术栈与选型理由

| 技术 | 用在哪 | 为什么选它 |
|---|---|---|
| Vue 3 + Vite | 前端框架/构建 | 主流组合，Vite 秒级热更新，面试必会 |
| Pinia | 状态管理 | Vue3 官方推荐，替代 Vuex，API 更简洁 |
| Element Plus | UI 组件库 | 国内使用最广，组件全，资料多 |
| ECharts | 图表 | 国产最强可视化库，心情曲线/热力图都靠它 |
| md-editor-v3 | Markdown 编辑器 | Vue3 原生支持，带预览 |
| Spring Boot 3.3 | 后端框架 | Java 后端事实标准，3.x 对应 Jakarta EE |
| MyBatis-Plus | ORM | 在 MyBatis 上增强，单表 CRUD 零 SQL，复杂查询仍可写 XML |
| MySQL 8 | 主数据库 | 关系型数据标配，支持 CHECK 约束、函数索引 |
| Redis | 缓存/黑名单 | 统计接口缓存 + JWT 登出黑名单，一石二鸟 |
| Spring Security + jjwt | 认证授权 | 企业级安全框架 + JWT 三件套 |
| springdoc | 接口文档 | 自动生成 Swagger，前后端联调利器 |
| DeepSeek API | AI 周报 | 便宜、国内直连、OpenAI 兼容格式 |
| Docker Compose | 部署 | 一条命令拉起全部服务，简历写"容器化部署" |

## 四、目录结构详解

### 后端 `backend/`（Maven 标准 + 按业务模块分包）

> 组织方式：**按模块分包（package by feature）**，而不是把所有 Controller 堆进一个 controller 包。
> 一个业务模块（auth、diary、tag...）的 controller/service/mapper/entity/dto/vo 都在自己的包里，
> 顶层只保留横切关注点（通用响应、异常、安全、配置、定时任务）。
> 好处：改一个功能只动一个包；模块高内聚、低耦合；包结构即业务地图，新人一眼看懂系统有哪些功能。

```
backend/
├── pom.xml                    # Maven 依赖声明，版本号集中在 <properties>
├── Dockerfile                 # 多阶段构建：Maven 打包 → JRE 运行
├── .dockerignore
├── sql/schema.sql             # 建表脚本（本地手动执行 / Docker 首启自动执行）
└── src/main/
    ├── java/com/daylog/
    │   ├── DaylogApplication.java   # 启动类，@MapperScan("com.daylog.modules")
    │   ├── common/                  # 【横切】通用能力
    │   │   ├── result/              #   Result<T> 统一响应 + ResultCode 状态码枚举
    │   │   └── exception/           #   业务异常 + 全局异常处理器
    │   ├── config/                  # 【横切】Security、Jackson、Redis 等配置类
    │   ├── security/                # 【横切】JWT 工具、JWT 过滤器、黑名单（认证核心）
    │   ├── scheduler/               # 【横切】定时任务（AI 周报、孤儿文件清理）
    │   ├── util/                    # 【横切】工具类（DeepSeek HTTP 客户端）
    │   └── modules/                 # 【业务】每个业务模块一个包
    │       ├── auth/                #   认证模块（注册/登录/登出）
    │       │   ├── controller/
    │       │   ├── service/impl/
    │       │   ├── mapper/
    │       │   ├── entity/
    │       │   ├── dto/
    │       │   └── vo/
    │       ├── diary/               #   日记模块（一天一篇 + 标签关联）
    │       ├── tag/                 #   标签模块（含使用次数聚合）
    │       ├── stats/               #   统计模块（趋势/热力图，Redis 缓存）
    │       ├── file/                #   文件模块（上传/关联/静态映射）
    │       └── report/              #   AI 周报模块
    └── resources/
        ├── application.yml        # 主配置：只放公共配置，默认激活 dev 环境
        ├── application-dev.yml    # 开发环境（IDEA 本地跑：localhost 直连 + SQL 日志）
        ├── application-prod.yml   # 生产环境（Docker：连接参数全走环境变量注入）
        └── mapper/                # 复杂 SQL 的 XML（注意：模块 XML 也放这里统一扫描）
```

**为什么 entity / dto / vo 要分开？** 数据库结构不该直接暴露给前端（密码字段、deleted 字段），入参和出参的形状也往往不同（创建时不传 id，返回时才有的 wordCount）。这是"分层解耦"的基本功，面试常问。

### 前端 `frontend/`（Vue3 工程标准结构）

```
frontend/
├── vite.config.js         # @ 别名、/api 代理、端口
├── Dockerfile             # 多阶段构建：Node 打包 → Nginx 托管
├── nginx.conf             # Nginx 站点配置（/api 反代 + /files 反代 + SPA 回退）
├── .env.development       # 开发环境变量（VITE_API_BASE_URL=/api）
├── .env.production        # 生产环境变量
└── src/
    ├── api/               # 接口请求，按后端模块分文件（auth.js、diary.js...）
    ├── assets/styles/     # 全局样式
    ├── components/        # 通用组件（被多个页面复用的）
    ├── layout/            # 页面骨架（侧边栏 + 顶栏 + 内容区）
    ├── router/index.js    # 路由表 + 登录守卫（history 模式）
    ├── stores/            # Pinia 状态模块（user.js：token、用户信息）
    ├── utils/request.js   # axios 封装：自动带 token、统一处理错误和 401
    └── views/             # 页面，按功能分文件夹（login/、dashboard/、diary/、stats/...）
```

## 五、数据库六张表速览

| 表 | 作用 | 关键设计 |
|---|---|---|
| user | 用户 | 逻辑删除；username 唯一 |
| diary | 日记 | **uk(user_id, record_date) 一天一篇**；物理删除 |
| tag | 标签 | uk(user_id, name)；物理删除 |
| diary_tag | 日记-标签多对多关联 | 联合主键 |
| attachment | 日记配图 | diary_id 可空，保存日记时回填 |
| weekly_report | AI 周报 | uk(user_id, week_start)，重复生成时覆盖更新 |
